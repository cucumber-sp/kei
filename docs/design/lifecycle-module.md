# Lifecycle module

The lifecycle module owns automatic destruction and copy hooks for managed values. The compiler creates one Lifecycle instance per compilation and shares it with the checker and KIR lowering. See [ADR-0001](../adr/0001-concept-cohesive-modules.md) for the module boundary.

## Decisions and generated hooks

- `decide.ts` computes which concrete structs need an automatic `__destroy` or `__oncopy`. The decision map is keyed by struct type identity and converges through a fixed-point pass; generic templates are handled through their concrete instantiations.
- A user-defined hook takes precedence over an automatic hook for the same operation.
- `synthesise.ts` emits KIR bodies for automatic hooks. Field destruction runs in reverse declaration order, as required by [the memory rules](../../spec/08-memory.md).
- The checker can query the decision through `hasDestroy`, `hasOncopy`, and `getDecision` without modifying the struct type.

A decision stores the names of managed fields. Synthesis resolves their concrete types after generic instantiation.

## KIR marker pass

Lowering records lifecycle operations as markers. `pass.ts` rewrites them between KIR lowering and mem2reg; later passes receive concrete instructions.

| Marker | Meaning |
| --- | --- |
| `mark_scope_enter` / `mark_scope_exit` | Delimit a scope and destroy its live tracked locals on exit |
| `mark_track` | Register a managed local in its scope |
| `mark_moved` | Exclude a moved value from later destruction |
| `mark_assign` | Replace a managed slot, including destruction and copy work |
| `mark_param` | Arrange destruction of a managed parameter on function exit |

The pass also consumes scope-exit metadata generated by lowering. It discovers both user-defined and generated hooks from KIR function names, so the same rewrite handles either kind.

## Order and boundaries

At scope exit, user `defer` blocks run in last-in-first-out order before automatic destruction. Managed locals and fields are destroyed in reverse declaration order. `defer` stays in KIR lowering because its scheduling is local to that stage.

Lifecycle handling for managed enum payloads remains open; see [SPEC-STATUS.md](../../SPEC-STATUS.md) and [remaining work](../roadmap.md).
